# Instructions for coding agent

Ты работаешь над существующим проектом Paint RAG.

Главная задача — не написать демонстрационный прототип, а постепенно довести существующий проект до рабочего состояния.

## Правила

1. Сначала изучи код.
2. Не делай предположений о существующей архитектуре.
3. Перед изменениями запусти pytest.
4. После каждого существенного изменения запускай pytest.
5. Не удаляй тесты.
6. Не ослабляй assertions.
7. Не добавляй mock вместо реальной функциональности.
8. Не переписывай работающие части без необходимости.
9. Предпочитай маленькие изменения.
10. Сохраняй обратную совместимость существующих API.

## При обнаружении проблемы

Если тест падает:

- определить причину;
- проверить модель данных;
- проверить реальные fixtures;
- исправить источник проблемы;
- снова запустить тест.

Не делать:

    "if test == ..."

Не писать код специально под конкретный assertion.

## Работа с PDF

PDF могут иметь совершенно разную структуру.

Нельзя писать:

    if filename == "PA334..."

или:

    if product_name == "..."

Парсер должен быть обобщаемым.

Допустимы:

- регулярные выражения;
- словари терминов;
- эвристики;
- extraction по страницам;
- нормализация текста.

## Работа с данными

Источник является истиной.

Если PDF говорит:

    15–30%

нельзя превращать это в:

    15%

Если указан диапазон, он должен сохраниться как диапазон.

Если значение отсутствует:

    null

а не выдуманное значение.

## Результат каждой итерации

После изменения сообщи:

- что изменено;
- какие файлы изменены;
- какие тесты запущены;
- сколько тестов прошло;
- что осталось сделать.

## Приоритет

Приоритеты:

1. correctness;
2. сохранение существующих тестов;
3. качество модели данных;
4. воспроизводимость;
5. простота;
6. производительность.

Не оптимизировать преждевременно.
